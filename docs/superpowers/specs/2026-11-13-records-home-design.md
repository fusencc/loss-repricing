# 提价记录首页设计

2026-11-17 用户选择十款预览中的 01「极光通栏」，授权改造现有前端：只保留部门切换，点击销售员自己的条目后，在当前页面中央弹窗查看详细日志。

- 深靛蓝、青绿与淡紫透光、连续玻璃表格；金额沿列对齐，姓名为定位入口。
- 主页每位销售员一行：记录数、最近商品、店铺/站点、最近价格变化、四态汇总与更新时间。点击整行或姓名打开本人全部日志；同名不同账号不合并。
- 中央弹窗紧凑展示商品/SKU、店铺站点、原实际价、目标实际价、建议上传价、提交记录价、回读价、处理状态与原因。移除业务日期、更新时间、商品/子商品 ID、执行进度、核验确认时间、保护起算时间、四价存档、观察时间及批次任务标识；高度随内容收缩。不跳转，支持关闭、Escape、键盘聚焦与焦点返回。
- 固定 Tiktok一部、Tiktok五部、Tiktok十二部、Tiktok二十二部四个部门按钮，同一行点击直接切换，无下拉弹出；无记录部门也可选择。移除周期/日期、搜索、主题、刷新、分页与详情按钮。2026-11-24 用户要求结果落库后及时更新，替换原 60 秒轮询：页面可见时通过服务器发送事件（SSE）接收已保存视图，服务端每秒检查变化；隐藏时关闭连接，重新可见立即读取，断线自动重连并提示可能过期。上传受理与实际生效核验仍分别展示。
- `/api/records` 替换旧日期分页合同，返回部门列表及所选部门全部历史记录。默认 Tiktok一部；接口保留未知归属证据，销售首页仅显示约定四部门。
- 部门只读同一完整商品键的 `trace.online_rows[].profit_check.department`；缺失/冲突明确待确认。人员只读当前 Ownership/UserAccount，目标级覆盖店铺级，缺失显示待分配。不推断主管或操作人就是销售员。
- 同日同完整商品键、同价格方案且只有一笔成功执行时，将成功之前的准备和失败记录折入成功记录的完整过程；不同店铺/仓配、不同方案、多次成功、未知执行及成功后的新记录均不合并。首页与人员统计按合并后记录计数。人员行按姓名首个 Unicode 字符的拼音排序，首字比较相同按全名，再按稳定人员 ID；同名不合并，“待分配”排在最后。多音姓遵循浏览器的简体中文拼音排序规则，不单独纠正读音。人员内部记录顺序和最近已提价摘要不变。
- 记录页实例只在内存保留已访问部门最近一次成功接收的完整视图。首次访问继续等待首帧；切回已有视图的部门先展示上次结果并提示正在更新，由同一条当前部门的 SSE 连接刷新，不增加查询或轮询，不预取或持久化业务数据。切换时清理人员弹窗和搜索，旧连接的回调不能覆盖当前或缓存数据；断线保留最近数据并提示可能过期。
- 日志页面展示状态映射为：已核验→已提价、待核验→待处理、待处理→待处理（2026-11-20暂停活动限制后不再显示为活动中）。部门顶部概览仅展示这三项统计，不展示“不调价”；销售员行及详细日志仍保留该状态。仅调整页面展示，原始记录与执行状态不变。
- 2026-11-23 日志当前布局：修正一次毛利、原营销价、需补亏损、利润校验变动、上传含税价使用同一个价格明细列表中的同层单元格，标签与保存金额共用样式，宽屏同排同顶线。执行状态独立于价格明细，在最右列顶部居中，不能与上传标签或金额堆叠；中屏将整组价格移到身份下方，窄屏价格按两列换行，状态仍位于右上方，不覆盖价格。仅展示保存金额与已有状态映射，不重算、不回写记录。
- 免登录只读边界不变，只返回白名单字段，管理接口继续认证；不公开来源快照、执行请求、内部成本或凭据。
- 演示、文件对账、真实接口按记录标注；不触发抓取、定价、提交或通知。
