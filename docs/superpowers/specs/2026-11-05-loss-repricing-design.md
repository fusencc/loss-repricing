## 销售协作与通知
销售员和主管通过权限网页处理所属商品。系统按当前商品归属鉴权，支持人工接管、明确交回、修正批准排队、外部价格冲突拦截及持久通知队列。钉钉选择企业内部应用定向工作通知；当前默认demo，真实账号/归属、权限、端内SSO应用发布及实际发送尚未配置验收。真实调价与数据源上线边界不因本扩展而解除。

“两边都会改价”指公司销售系统和平台后台的描述仍待核实，不视为两个外部系统历史接口、操作者来源或独占写入能力已确认。coordination_required本地默认true、生产强制true，false用于隔离协作之外的测试；live_writer_exclusive默认false，须核实外部来源和写入独占。接管不清未知锁，批准不等于执行，发送受理/钉钉已读/网页业务确认/价格生效分别留证，未知通知不重发。

当前详细规则以[销售协作设计](2026-11-05-sales-coordination.md)及[销售协作操作说明](../../sales-coordination-runbook.md)为准。

## 数据到定价的连续接入

真实数据采集、过滤和补亏计算作为连续业务流程接入。采集结果须有明确的下游消费方。只读评估使用已确认的数据来源，真实提价单独授权。

### 目标流程与交接责任

完整流程为：真实候选采集 → 订单到在线子SKU关联 → 规范化转换与独立来源补齐 → 规则过滤与补亏计算 → 执行授权 → 提交 → 实际有效价核验。每个环节都必须有明确的输入、输出、来源引用及下游调用方，不能把采集文件保存成功视为已完成定价接入。

- **采集与商品关联**：复用已确认的ERP批量下载和任务绑定能力，保留四类候选与订单财务原件；按经核实的明细及在线来源建立订单明细、店铺、站点、产品、具体商品、子SKU、主SKU和仓配的可靠关联。订单财务金额不直接当作当前在线售价，SKU列表不直接当作规范明细，多SKU整单亏损不任意分摊。
- **规范化与来源补齐**：由`adapters`承担来源字段转换，并关联当前价格及折扣、七完整日销量、保护／活动／生效历史、有效汇率、公司费用模型及站点合同，构造定价使用的规范`Snapshot`。来源版本、公司费用版本、站点合同版本与本项目公式版本分别留证；缺失字段、币种、数量粒度或金额语义不靠默认值补齐。
- **统一任务编排**：由`services`组织采集结果消费、数据准备与现有定价服务，API／worker提供入口和持久调度；真实定价取数必须实际调用已实现的来源能力，不继续维护一套与批量采集脱节的取数路径。已保存采集可用于明确选择的文件对账；实时执行及提交前刷新仍须使用业务日期、时效和范围有效的数据，不能自动选最新文件或回退旧文件。
- **过滤与计算复用**：规范数据交给现有领域引擎，统一执行保护、销量、历史、单件化、最小亏损、换汇、折扣及毛利复核；采集器和前端不复制价格公式。来源筛选与定价排除分别记录，确保能解释某笔订单在哪一步停止、某个商品为何不调或待处理。
- **网页状态关联**：网页须关联采集编号、数据准备结果和定价批次，区分抽样诊断、正式候选采集、过滤／计算结果与执行结果。不能用抽样成功、文件回读一致或模拟批次成功表示真实链路已接通。

### 数据评估与真实提交分开控制

- 真实提交开关关闭、试点名单为空，或上传／有效价查询合同未完成，均不应单独阻断已具备数据条件的只读过滤与计算。数据就绪、计算结果与提交授权分别判断和展示；未授权提交必须保持零价格上传调用。
- 只读评估同样需要已确认的数据来源及计算依据。四候选的同范围完整性、当日汇率、商品身份及费用模型等既有计算检查继续有效；缺少什么就记录什么，不为了生成价格绕过检查。能够可靠定位的单条问题只阻止该目标的不安全操作；公共来源完整性确实无法证明时，才阻断其影响范围内的计算。
- 采集候选与转换失败记录须保留可查询的原因和来源定位，不能丢弃无法映射的记录后用“零候选”冒充全部处理完成。无法确定商品身份的记录在数据准备结果中留存，不伪造商品键生成定价记录。数据准备阶段信息不替代现有四个业务状态，也不把已计算标为已提交或已生效。
- demo、file、live继续隔离数据库、运行目录和历史证据；真实数据对账不得借demo模拟回执充当真实验收。真实上传继续受开关、明确试点、站点合同、协作授权、持久意图及防重控制；提交未知只核验、不自动重传。

### 实施顺序与验收边界

1. 先贯通已采集真实订单到数据准备结果的追踪，核实并接入在线子SKU关联及亏损粒度；单笔样本用于验证字段交接，不代替四来源完整性验收。
2. 补齐独立来源，使用真实数据在隔离的只读对账环境验证规范化、过滤和补亏计算。逐条核对来源、排除原因、选中亏损及计算过程；缺条件的记录应有具体原因，而非消失或填零。
3. 将同一转换逻辑接入实时定价取数及后台编排，网页能够从采集追踪到批次；验证同范围四来源完整性、跨日重取、刷新及单条异常不影响独立记录，并证明关闭提交时不调用价格上传。
4. 在上述数据链路成立后，再按明确授权完成真实试点提交与实际有效价核验。只读链路通过、接口受理及模拟核验均不代表真实提价生效。

当前已保存批次可在管理员页面从 ERP 商品明细和销售在线变体原始导出核对在线目标，生成数据准备报告。附版本化证据后，按原始行引用、目标和数量复核，再组装规范快照并只读算价。隔离文件模式中，管理员可将选定报告的规范快照和原判定保存为带来源链接的对账批次，在批次历史中回看。入口与字段见 [ERP 采集对账与只读算价](../../erp-pricing-preview.md)。实时取数、独立来源的真实合同、生产批次关联及试点仍按上述顺序接续，以相应的验证证据验收。

- 每个具体在线子SKU分别在同店、同站、同仓配、同费用和币种口径下取最小有效单件亏损；不跨子SKU取小。11/3字幕[343]37:16明确同一SKU不同订单，[360]/[363]38:53–39:12选择最低。10/19[060]11:18–11:54区分产品ID与具体SKU商品ID。之前误点的父产品共享最小值已撤回。

- 生产只保留关键业务核验。经用户授权的格式兼容和边界组合在离线测试覆盖，避免运行批次重复执行全量测试或要求逐批人工确认。

## 方案选择
后端使用 Python、FastAPI、SQLAlchemy、Alembic 和持久 worker，前端使用 Vue 3、TypeScript 和 Element Plus。生产目标数据库为 MySQL，演示使用 SQLite。公式以 Decimal 实现，Excel 用于核对结果。本项目与广告预算业务隔离。

## 真实集成界限
旧程序已具备认证、在线导出、历史查询、Excel上传与最新成功价请求；未证明四份ERP筛选、真实有效价和完整逐行/任务关联合同。客户端应支持这些边界，但不能编造字段或以模拟验收替代生产验收。实际试点店铺尚未指定，默认空名单和真实提交关闭。

## 数据与算价说明
每批保存标准化快照与来源引用、字段映射/合同版本、汇率日期和公司费率版本。费用模型用经确认的一次毛利仿射参数表达：normal_profit(P)=P*revenue_factor-fixed_cost，均为站点币，不能直接套旧模板15%目标利润或把未知费用默认为零；未确认模型不自动执行。最终需用真实公式/样本证实参数与公司口径等价。

## 验收
自动真实取数到有效价核验至少一组合格试点，关键规则/故障恢复测试通过，重启可恢复且未知结果不重传。当前未指定试点/未完成真实合同的情况必须如实显示和记录，不能标记上线完成。
