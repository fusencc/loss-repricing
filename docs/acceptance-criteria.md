# 亏损补亏项目总体验收标准

## 1. 项目目标

针对亏损订单对应的在线商品，完成从数据获取、补亏价格计算、销售协作、价格调整到结果核验的业务闭环，减少人工整理和重复操作，并使处理过程可查询、结果可追溯。

## 2. 核心验收标准

| 验收内容 | 达成标准 |
|---|---|
| **数据获取准确、完整** | 能获取约定范围内的 ERP 亏损及禁止发货订单，并关联对应的在线商品、价格和计算所需数据；与人工查询或导出核对一致，缺失或不确定的数据有明确说明。 |
| **补亏计算符合业务规则** | 按已确认的补亏规则筛选商品并计算价格；能够说明为什么调价、为什么不调，以及价格如何得出；代表性案例经人工复核一致。 |
| **销售能够参与处理** | 能通过钉钉向对应人员通知详细的调价处理情况，方便他们核对。 |
| **调价正确并确认生效** | 能在授权范围内将确认的价格提交到对应商品，并查询实际生效结果；明确区分待处理、待核验和已生效，未成功的事项有原因和后续处理入口。 |
| **过程可查、系统可用** | 能查看数据来源、计算依据、处理记录和最终结果；系统能在约定环境运行，完成日常任务，并提供必要的使用及维护说明。 |

## 3. 阶段验收

1. **数据阶段：**完成约定数据范围的获取、保存和人工对账，证明数据可以支撑补亏业务。
2. **计算与协作阶段：**完成价格计算、网页处理和销售协作，以代表性业务案例验证流程及结果。
3. **真实试点阶段：**在明确授权的店铺、站点及商品范围内，完成真实调价并核实实际生效。
4. **正式交付阶段：**在约定环境部署运行，交付使用说明、验收记录和遗留事项清单。

阶段通过只代表该阶段及已验证范围完成；模拟演示和本地测试通过，不等于真实业务上线完成。

## 4. 验收边界

- 业务规则沿用已确认口径，尚未确定的规则先确认，再纳入验收。
- 本项目处理亏损订单关联商品的补亏，不扩大为全店普遍涨价或其他尚未确认的业务。
- 限流、重试、阻断、防重、恢复及其他技术实现细节，在实际开发设计时确定，不在本总体验收标准中展开。
- 项目最终完成，以**约定范围内真实业务闭环通过、结果经过复核、使用方能够实际使用**为准。
