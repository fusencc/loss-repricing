### 0. 变量与金额口径

- `L`：ERP 下载字段「修正一次毛利」的负金额，币种与金额粒度由来源合同确认；不是亏损率，也不是本程序重算或修正的毛利。原始金额必须保留符号。
- `q`：该金额所对应的可售件数。整单件数不能冒充某一子 SKU 的明细件数。
- `u`：正的单件亏损幅度，单位为原币/件；`Δ` 为转换后的站点币/件。
- `R`：当前含增值税（VAT）的零售价；`P`：当前实际营销售价，无营销价时为 `R`。二者均为站点币/件，不能用订单实付总额替代。
- `d`：实际价与含税零售价的比例，无量纲；`T` 为未做上传档位舍入的目标实际价；`Uraw` 为未舍入上传价；`U` 为最终含税上传价；`P'` 为折扣不变假设下的舍入后实际价。
- `a=revenue_factor`：完整在线利润收入系数，无量纲；`b=fixed_cost/fixed_cost_divisor`：每件固定成本，站点币/件；`G(P)=a×P-b` 为所选仓配每件完整在线利润额。固定成本已经用站点币计价时，单位比值为1；公司来源若提供CNY成本及明确的CNY/站点币报价，直接保留这两个原始有限小数，由统一MoneyRatio公式精确相除，不先截断循环小数。报价必须属于费用来源，不能用ERP亏损换汇报价代替公司费用报价。
- 完整在线利润校验包含所选仓配公式规定的全部费用。具体包含哪些税、物流、佣金及固定费用，须以公司批准的分项公式为准；不能从显示取整的毛利率倒推成本，旧模板也不是本期自动批准的费率表。

### 0.1 数值、空值与证据要求

核心引擎使用 `Decimal` 分子与正分母保留单件化、换汇及折扣运算的精确关系。有限小数乘加按所需位数计算，最小值和误差用交叉乘积比较，价格档位用商余数判断整档与半档，毛利按精确分子的符号判断；不使用 `float`，也不加容差把负毛利视作零。实现集中在 `domain/money.py`。

保存和展示的普通小数使用独立上下文的 **50 位有效数字**，不是 50 位小数；循环小数仍是近似显示，不能再读回这些显示值决定档位或毛利正负。新增判定另保存目标价的精确分子、分母及算术实现标识 `decimal-ratio-v1`，用于有效价容限核验。`loss-erp-corrected-margin-reference-priority-20261123-v14` 保留精确比值算法，参考上限优先于利润要求。

例如明细亏 1、数量 3、当前实际价 1、零售价 3，精确上传原价为 4；先把 1/3 截成有限小数再向下舍入可能错误上传 3.99。又如当前价 10、单件亏 1/3、模型 `0.9×P-9.3`，目标毛利精确为 0，不能因小数尾差误判为负。两者均有独立回归测试。

金额与费率对外优先使用十进制字符串；真实 HTTP JSON 数值直接解析为 `Decimal`，不能先过 `float`。ID 必须为文本。时间必须带时区，业务日期按北京时间。Excel 数值单元格受 15 位有效数字限制，当前模板生成器会拒绝超范围价格；文件可生成不等于真实服务认可该列。

缺失不能等于零：无营销价的空值表示已确认无折扣；未知营销价应停止该目标算价，不能传空冒充无折扣。历史 `null` 只有结合 `history_known=true` 才能表示确证无历史。`history_known` 和 `allocation_reliable` 缺失时默认 false，不能从“未提供证据”推导“已确认”；整单分摊不可靠时不参与选取，单件/明细粒度不依赖整单分摊标记。费用模型为空不设默认成本或默认系数。其他无活动/无保护等布尔值也必须有来源证据；真实 HTTP 合同要求显式映射，内部模型的默认值不构成真实数据合同。

每条判定保存规则版本、数值精度、来源引用和版本、汇率日期、模型与站点合同，以及选择明细和算价中间值。新增判定写入 `trace.formula_version`；旧历史没有此字段时按旧记录展示，不倒填为已经过新版本重算。

### 2026-11-25 ERP 实际采集范围

用户授权实时 ERP 按“抓到多少处理多少”处理。后页或独立财务子批失败不否定已下载、逐批请求范围及金额证据对齐的订单；实时财务缺行只排除该订单，同目标其他可靠亏损样本继续参与取小。同页无效记录留原因后排除。最小亏损仅代表本轮实际采到的有效样本，不代表冻结全量名单中的最小亏损。

## 2. 每个子SKU独立取最小亏损

算价时的来源匹配身份由平台、店铺ID、站点、产品ID、具体商品ID、子SKU共同确定，ID保持文本。仓配、主SKU与费用口径还要与在线快照一致；同一身份出现冲突不会自动选一条。`VariantKey.identity()`保留源SKU，防止不同SKU的亏损混算。

防重另用`VariantKey.target_identity()`：平台、店铺ID、站点、产品ID、具体商品ID。这是实际上传对象的稳定身份，不含可变的源SKU名称或仓配；源SKU改名不能绕过未知执行锁和72小时保护。**稳定执行锁不改变算价分组，不允许把不同SKU的亏损混在一起取小。**

同一在线子SKU内，原始行ID用于跨来源去重。同一行ID出现相互冲突的金额、数量或口径会待处理；不能仅用订单号或SKU去重，因为一张订单可以有多个明细。相同平台、店铺、订单号和明细行 ID 如果指向多个在线变体，相关变体均待处理。不同订单或店铺的同名明细 ID 不触发这项映射冲突。 ERP 预览和通用 HTTP 取数均将订单号、明细号编码为同一份规范快照行 ID。分页完整性和取最小亏损时因此能区分不同订单的同名明细。 同一来源分页中，平台、店铺和规范明细 ID 重复即视为分页异常，商品映射不同也不增加来源明细数。

原始亏损记作负数`L`，数量为`q`。先得到正的单件亏损幅度`u`：

```text
已是单件金额（basis=unit）：u = abs(L)
明细金额（basis=line）：    u = abs(L) / q
整单金额（basis=order）：   只有已证实可可靠归属到单个 SKU 明细时，u = abs(L) / q
```

数量必须大于0；非负金额不进入亏损候选；异常记录和无法可靠分摊的整单金额不参与取小。若没有有效记录，转待处理。同平台、同店铺、同订单号在快照中若已见多条不同明细，整单金额不参与取小，即使输入标记为可分摊；原始明细级金额和其他订单的有效金额仍可参与。可定位的异常明细仍计入订单明细数。跨来源出现同一明细不增加明细数。仅观察到一条明细仍需可靠归属证据。

然后**仅在同一个具体在线子SKU、同店、同站、同仓配、同币种及同费用口径的有效明细内**选择最小`u`，保留被选中的原始行ID和所有参与值。两个不同子SKU即使产品ID相同，也分别计算：

| 具体子SKU | 有效单件亏损 | 选用值 |
|---|---|---:|
| A | 1、2 | 1 |
| B | 3、4 | 3 |

B不会使用A的1。这里“最小亏损”指正亏损幅度最小：原毛利`-1`与`-2`中选亏1，不是按负数数值取`-2`。主SKU维度只在人工保护等已确认规则中汇总，不用于共享亏损金额。

### 2026-11-11 公司当前配置的业务使用日

用户明确选择使用运行当天查询到的公司当前汇率配置，并记录当天为业务使用日。
自主入口在本次 ERP 抓取后重新查询汇率，将原配置及规范转换结果单独保存到 `runtime_dir/source-fx/`。
`date_policy=current_config_on_usage_day`，`date` 为查询时点对应的北京时间业务使用日；`source_effective_date` 仍为空。
这项业务约定没有补造接口生效日期。查询和采集跨业务日时不能合并，实时汇率不自动注入历史文件回放。
原币／人民币结算栏和销售费用参数的站点汇率单位按 CNY／原币核对。ERP当前配置以原报价及 `fx_rate_unit=cny_per_currency` 进入统一精确比值计算；独立50位倒数仅供展示，字段为 `display_units_per_cny`，不得回读为算价输入。
例如配置为3 CNY/MYR，3 CNY亏损精确补1 MYR，不把显示的1/3近似值带入向下取整。原配置、单位和日期策略随报告保留。
公共查询失败或人民币基准无效时继续保存缺项，不取旧日配置、不填默认值；个别无效或非标准币种不进入规范汇率，受影响商品由引擎记录缺项。

规范文件的 `fx_rate_unit=currency_per_cny`，此时 `fx_rates[C]` 表示**每1 CNY可兑换多少C币种单位**，且`fx_rates[CNY]=1`。例如每1 CNY对应0.6 MYR，MYR汇率为0.6。ERP当前配置则明确携带 `cny_per_currency` 单位，不混用数值。

```text
站点币补亏额 Δ = 单件原币亏损 u × 站点币每CNY汇率 / 原币每CNY汇率
以CNY/原币报价时：Δ = u × 亏损币的原报价 / 站点币的原报价
```

例：CNY单件亏2，当日MYR汇率0.6，补亏额为1.2 MYR。同币种直接保留原值。内部站点币为MY→MYR、PH→PHP、SG→SGD、TH→THB、VN→VND。

原WPS模板用RMB成本除以AC汇率换成站点币，其AC在该公式中的方向与本程序相反。真实接入必须根据已确认单位转换，不可直接抄AC数值。缺币种、缺正数汇率或汇率日期错误时待处理。

## 4. 当前实际价、折扣与上传价

令`R`为当前含VAT零售价，`P`为当前实际售价：有营销价取营销价，无营销价取`R`。无折扣来源应传空值，不用零元价表示“无折扣”。必须满足`0<P<=R`。

```text
成交系数 d = (100 − OFF) / 100（销售系统确认的百分比折扣）
无折扣： d = 1
初步候选价 T0 = P + Δ
在线利润校正额 C = max(0, 在线利润校验通过的最低实际价 - T0)
未限价目标 Tfree = T0 + C
有参考上限 A 时：Umax = 向下取整至上传档位(A/d)，T = min(Tfree, Umax×d)
没有参考时：T = Tfree
未舍入的含VAT上传价 Uraw = T / d
```

`d`是成交比例，不是“减价百分比”。旧表里折扣55代表减55%、成交45%，不能直接当作`d=0.55`。销售批量表直接读取「折扣」原值作为 OFF，营销价仍用表内实际售价。已有只提供实际价和零售价的入口按 `P/R` 取成交比例。折扣只改变成交系数；上传列的税价口径由经验证的店铺类型和仓配合同决定。2026-11-09「提价需求」群提到本土店税前列，目前未纳入本程序的含VAT上传范围，需以独立样本确认，不从有无折扣推断。

批量预览和单品活动检查允许营销实价与含税零售价乘成交系数相差不足一个币种显示单位（VND 为 1，其余站点币为 0.01）。算价继续使用来源提供的原始 OFF。

每个站点合同必须明确适用仓配 `warehouses`、价格档位 `step`、舍入方式、税后上传列和版本，才能计算。仓配列表默认空，未明确覆盖该商品仓配时只挂起该目标；提交边界再次核对相同范围。此列表表示这些仓配已经确认可共用该上传列和费用版本，不是仅凭“直发/海外”字样猜列。需要不同列或不同模型的仓配，当前单站点合同不能同时覆盖，须分期接入或先扩展设计：

```text
档位数 n = round(Uraw / step, 合同舍入方式)
上传价 U = max(n × step, 1%最低通过上传价向上取整)
有参考时再限制 U = min(U, Umax)
舍入后实际价 P' = U × d
实际价误差 ε = abs(P' - T)
```

支持的舍入方式是`ROUND_HALF_UP`、`ROUND_DOWN`、`ROUND_UP`。按档位数舍入可以支持0.025等步长，不等于固定保留两位小数。测试样本采用的0.01/1档位和四舍五入只是模拟合同，不能作为公司站点规则。

当前误差容限为VN≤2 VND；MY/PH/SG/TH≤0.02对应站点币。上传价非正、误差超限时待处理。真实回读误差超限仅标记该条 mismatch 并保留目标锁继续核验，不自动暂停站点。

通用档位合同保留三种舍入方式；没有参考时仍保证1%利润档位，有参考时以上限为准，允许低于利润档位。实际接入采用11/11确认的向上取整，上限档位单独向下取整。当前规则没有额外要求 `P'>P` 或最小涨幅，参考低于现价时允许降价，等于现价时允许同价。

`P'=U×d` 还依赖“上传零售价后成交系数保持不变”。算术正确不证明平台会保持折扣；固定营销价、活动覆盖、税前/税后转换可能使该假设不成立。每个试点站点及仓配必须用上传前后实价证实，未证实的范围不启用真实自动提交。

提价日志中的「一次毛利」展示算价选中的 ERP 订单级修正一次毛利原始金额与币种，保留符号，不换汇、不单件化。只有从判定留存证据中唯一匹配到该来源时才展示，否则显示「未记录」；不影响算价和执行。

提价日志的「上传含税价」只展示执行请求记录中的站点币含税上传价；没有请求金额时显示「未记录」，不以算价建议或平台回读价补齐。请求记录不代表平台已受理或价格已生效。阶段表保留各环节站点币价格、相对上一环节的人民币增量与百分比，不展示各环节价格的人民币折算值。

## 在线利润校正额（当前规则）

### 变量、分流和来源
`profit_check` 是独立必需的计算证据：`overseas_stock`、`mode`、`department`、`inventory_observed_at`、`source_ref`及完整在线费用`model`。2026-11-20用户更新：库存>0选择`overseas`，=0或缺失选择`direct`；缺失字段、null或空字符串规范化为null，不伪造为0，`trace.warnings`保存“海外库存缺失，已按直发模型计算，请核实库存”，商品详情显示告警，常规及人工修正共用。负库存、无效值、模式不符、归属不明确、来源非当日或版本未确认仍阻断该目标。参考优先改变利润要求，不放宽身份、费用来源、仓库匹配或提交授权。公式版本为`loss-erp-corrected-margin-reference-priority-20261123-v14`，历史记录不回填。只计算选中的仓配公式。 2026-11-25 确认海外库存明确为零时按直发处理，ERP 订单默认仓名与销售当前默认仓名可以不同。名单提交前重新核对海外库存和仓配模式。

亏损金额直接来自 ERP「修正一次毛利」，新价使用当前部门费用的完整在线模型。海外仓完整模型保留营销费；显示利润率只作对账，不从取整值反推成本。`totalRate` 和 `totalCost` 仅检查分项合计，允许绝对差分别不超过 0.01 个百分点及 0.01 CNY/件，保存实际差额，仍按完整分项精确求和算价。结构性缺项、币种报价无效、多个有库存仓位、采购或头程不唯一、直发明细仍有海外库存时，只阻断受影响商品，在在线准备异常清单记录商品身份和原因。利润率、档位和实际价格核验不使用这项容差。HTTP 合同独立保留 `profit_check` 映射和 `online_profit_model_version`，旧合同不自动升级。

### 当前算式

```text
T0 = P + Δ                       # 原单件补亏候选价
Gonline(P) = aon × P - bon       # 部门完整利润额，站点币/件
Monline(P) = Gonline(P) / P       # 利润率；P>0时与利润额同号
B = bon / (aon - 0.01)          # 所选在线利润公式校验通过的最低实际价，aon必须>0.01
C = max(0, B - T0)              # 在线利润校正额，站点币/件；校验已通过则为0
Tfree = T0 + C                 # 未限价目标；等价于max(T0, B)
有参考A：Umax = 向下取整(A/d)，T = min(Tfree, Umax×d)
无参考：T = Tfree
Uraw = T/d
U = max(合同档位舍入(Uraw), 向上取整(B/d))
有参考：U = min(U, Umax)        # 参考优先，B不可求时直接U=Umax、T=Umax×d
P' = U × d                      # 如实计算利润；只有无参考时要求至少1%
```

统一业务名称为「在线利润校正额」，指初步补亏价通过库存对应完整在线利润校验还需增加的实际价金额；不是利润额、上传价增量或额外的独立一次毛利门槛。`trace.online_profit.correction_amount`保存该值，单位为`trace.station_currency`，不包含后续档位与平台回读差异。历史记录未保存该值时显示「未记录」，不回填或在前端重算。

没有参考时最低在线利润率为1%，求解最低通过价以避免无界逐分试价；不以误差或显示取整掩盖不足。有参考时优先上限，利润可以低于1%或为负，不再作为算价、人工及回读的否决条件。全程Decimal精确比值，保存初始候选价、校正额、可求的最低通过价、部门、库存与时间、完整模型版本及实际预计利润率。`Decision.predicted_profit`为档位后所选仓配完整在线利润额；`trace.target_profit`为目标价完整在线利润额，利润率及`minimum_margin_required`在`trace.online_profit`保存。旧批次保留原始公式版本与记录。

例：P=10、原补亏Δ=1.2、完整利润=0.8P-10，T0=11.2；1%最低通过实际价为10/0.79≈12.6582278481。无参考时无折扣上传12.66，五折上传25.32；若参考12.5则实际价按12.5调整，五折上传25，利润0仍可通过。若参考9则实际价降至9，五折上传18，利润-2.8仍可通过。人工指定价格只校验不自动改写：无参考时未达1%需修正，有参考时不因利润不足拒绝。
