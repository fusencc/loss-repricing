# 代码设计与变更规范

适用于本项目后端、前端、测试及部署脚本。业务口径以[已确认设计](superpowers/specs/2026-11-05-loss-repricing-design.md)为准，公式细节统一维护在[核心计算规范](calculation-and-sources.md)。本文规定开发方式，不是生产接入已完成的声明。

## 1. 分层与职责

### 数据模型与纯计算：`backend/app/domain/`

- `types.py` 定义内部规范模型，不把内部字段名冒充公司接口字段。
- `engine.py` 只接收快照和显式评估时间，返回判定与过程证据；不请求网络、不访问数据库、不读取环境配置、不上传价格。
- 所有业务价格只在后端计算。规则分组保留来源子 SKU；执行锁使用实际上传目标，两种身份用途不同，不能合并成一个键。
- 规则修改必须说明设计依据、增加边界测试，并更新公式规范和规则版本。仅补注释、修复实现与既定公式的偏差不等于另立业务公式；需要在验证记录说明兼容影响。

### 外部系统边界：`backend/app/adapters/`

- `normalization.py` 负责字段映射、类型、单位、币种、数量粒度和来源时间；`http.py` 负责合同检查、请求及响应转换；`excel.py` 负责已确认上传模板。
- 真实取数必须提供字段证据、版本和适用范围。转换注释用中文说明来源字段、单位、币种、日期、缺失值和已确认/待确认状态。
- 只映射价格字段不等于取数完成：还需数量、唯一身份、保护、历史、活动、费用模型以及源时间。
- `demo` 只使用合成数据与模拟回执；`file` 只读规范快照对账；`live` 使用已确认合同。禁止失败后偷偷改用 demo 或旧文件。
- HTTP 超时与返回异常不得被解释为零数据、无历史或未提交。上传只发一次；查询可重试，未知提交不可自动重发。
- 缺少某站点合同只阻断该站点。HTTP 采集将可定位的记录异常写入 `Snapshot.source_issues`，引擎挂起受影响目标及依赖同一在线销量的商品。无法定位记录、列表或分页不完整、业务日或公共汇率检查失败时停止整批取数。

### 执行编排与持久化：`backend/app/services/`

- `PricingService` 负责取数、纯计算、执行授权、提交前刷新、目标锁和核验；不复制公式。
- `store.py` 负责任务、配置、审计和当前记录视图；全局当前状态与批次历史分开。新评估不能遮住旧未知提交，也不能回写历史计算来制造“当时已通过”。
- 外部上传前先提交包含执行意图和目标锁的事务；事务完成后才发网络请求。网络失败不得回滚为“从未提交”。
- 锁以实际上传目标为粒度。历史时间取最近已确认生效时间；旧请求晚核验不得倒退历史。已有多笔未知执行要全部终结，才能解除占用。
- 单条重评只执行选中目标；允许共用完整采集快照，但不顺带提交其他目标。跨北京时间业务日重新取数，旧请求继续核验。
- 核验不受“暂停新提交”开关影响。站点超差只暂停该站点，其他独立站点继续。

### 调度、API 与界面

- `worker.py` 只负责持久任务、租约、定时和恢复；不可绕过服务直接上传。
- `api/` 负责登录、权限、输入验证、任务入队及查询；页面动作不直接承担耗时外部改价。
- `frontend/` 展示后端返回的十进制金额与证据，不用 JavaScript `Number` 重算上传价、毛利或核验容限。
- 四个用户状态为“本轮不调、待处理、待核验、已核验”；提价日志按用户授权仅在前端将待处理与待核验合并为“待处理”，数量相加、筛选同时命中两者，原始状态及执行动作保持不变。内部执行阶段另行展示。`ready=true` 只表示算价通过，仍可能被试点/暂停/合同限制阻止。
- 提价日志阶段名称仅在显示层将「补亏损」展示为「补毛利亏」、「利润校验」展示为「利润校验变动」，去除阶段序号；「参考价优先」等其他语义保持原样。原始阶段键、历史标签及金额不回写，不在前端重算。SKU 与具体商品 ID 按原始文本复制，不含展示前缀；缺失时不提供复制，只有浏览器确认写入后才提示成功，失败明确提示手动复制。商品 ID 的前缀和值保持整行，隐藏其复制图标，仅 SKU 保留图标；商品 ID 文本仍可点击或用键盘复制，并保留读屏名称和悬停提示。身份列为完整 ID 留出宽度，极窄屏将身份、状态和价格分行排布，不裁剪 ID 或覆盖金额。复制反馈使用 Element Plus 消息浮层，成功 2 秒、失败 3 秒后自动消失，不在标题或商品 ID 下插入提示或占位。
- 提价日志执行状态独立占右列，徽标下展示本条保存的 `reason`（待处理含待核验、本轮不调）；缺失明确显示「原因未记录」，不从销量、价格或历史尝试推导原因。已提价说明固定为「商品符合调价」。商品身份店铺行仅显示店铺／站点，底层平台身份及导出字段保持原样。本展示不新增七日销量阈值保护。弹窗标题仅显示人员和日期证据，不保留总数/命中数事件或状态；全部、已提价、待处理、本轮不调按钮始终显示该销售员完整历史的数量（含零），关键词与状态筛选不改按钮数量。标题日期采用北京时间，平台明确 `effective_time_source=effective_at` 的已核验记录标「提价生效日期」，首次核验时间标「提价核验日期」，其他仅有更新时间的记录标「记录更新日期」；多日显示范围，混合证据分类标示，缺失明确未记录，不用今天补齐。
- 提价日志弹窗标题不展示总条数或筛选命中数，状态按钮保留本人完整记录的数量。标题日期仅投影 `/records` 已保存的证据：已核验且 `effective_time_source=effective_at` 使用 `execution.effective_at` 标注「提价生效日期」；首次核验 `execution.confirmed_at` 只标注「提价核验日期」，不冒充真实生效；其他仅有 `updated_at` 的记录标注「记录更新日期」。同类日期显示最早至最晚范围，统一北京时间与中文年月日格式；缺失、无效或无时区的时间不猜测业务日或今天，显示「提价日期未记录」。标题、日期和下载按钮自然排列并换行，关闭按钮保留独立空间。
- 批次 `completed` 只表示这次处理结束，不代表商品全部涨价或生效。`accepted` 只是受理；demo 的 `verified` 必须说明是模拟核验。

### 计算层组织（2026-11-23）

- `domain/fee_calculation.py` 根据规范化的金额和百分数计算直发超重档数、站点币运费、含 VAT 的每件固定成本和完整在线利润系数。
- `adapters/sales_fee_model.py` 解析销售系统库存 JSON，核对仓位、采购和头程成本归属、币种以及费用分项合计，随后调用计算层并保存来源证据。
- 费用与物流只从销售系统每日快照组装，部门及物流按站点、本土和3PF属性唯一匹配；不保留旧表导入或另一路费率选择器。每日检查、内容版本和本批次引用分别保存；同日跨批次与进程复用，跨日再查，未变内容不换版。泰国直发类目VAT仍取当前父商品。缺失或歧义只影响对应目标。
- `engine.fx_ratio` 根据快照里的报价单位和币种取精确比值。同币种也核对当日报价。自动与人工算价共用 `OnlineState.actual_price_and_discount()`，以同一成交比例反推上传价、复核进档后实际价。
- `OnlineProfitCheck.validation_issue()` 按仓配、来源和模型依次校验，调用方使用对应的中文原因。`minimum_actual_price()` 返回 1% 利润的精确价格下限，无正价可达时返回 `None`。Top3 参考展示与上限使用同一组样本计算均价，档位比较使用精确分数。

## 2. 数据与金额约定

1. 金额、费率、价格步长使用 `Decimal`；跨 JSON/API 优先传十进制字符串。禁止 `Decimal(float_value)` 修补已发生的二进制精度损失。
2. 金额链路用 `Decimal` 精确比值延迟除法，档位/容限/毛利符号不依赖循环小数近似；保存和展示小数使用独立 50 位有效数字上下文。Excel 精度限制单独处理，不把文件可写视作外部服务已接受。
3. ID 使用文本，不转整数、不丢前导零。未知、空值和确证的零是不同状态。
4. 时间必须带时区；持久化采用 UTC，业务日与七天销量窗口采用北京时间。API 不隐式猜秒/毫秒或当地时区。
5. 字段映射、费用模型、站点合同、公式规则分别版本化。`verified` 是审批结果的配置表达，不能代替证据、审核人、日期及适用范围。
6. 变化的数据不得复用过期验证。相同有效范围内的检查可以复用，避免每件商品重复全量导出；当前批次刷新策略见计算规范第 6 节。

## 3. 错误与执行结果

- 使用具体原因说明错误事实及最小阻断范围，禁止 `except: pass` 后继续提交或伪造成功。
- 外部提交边界允许捕获未知异常并标记 `unknown`，前提是保留原执行与锁、记录脱敏原因、后续只查询。这是明确的未知状态，不是吞错放行。
- 经用户授权的输入格式兼容、边界组合和故障演练放在测试中；生产只执行影响安全改价的检查。
- 行级拒绝必须能关联本次文件/行/任务。未知字符串、未列出错误的行、接口 `resp_code=0` 均不足以证明价格生效。
- 当前有效价必须属于同一商品、仓配、币种和实际含税价口径，并有提交后的来源时间；任务拒绝需绑定本次执行。具体接口是否提供这些证据仍需真实联调。
- 不引入无依据的额外涨幅、利润目标、全局停机规则或逐批人工批准。

## 4. 测试分工

- `tests/test_pricing.py`：分组、单件化、保护、日期、换汇、折扣、档位与利润规则。
- `tests/test_formula_contract.py`：文档中的手算例子；以精确有理数独立对照换汇和舍入，不复用被测函数生成期望值；验证上下文精度隔离和微小负毛利。
- `tests/test_live_adapters.py`：模拟 HTTP 的请求映射、分页、合同关闭、模板、回执及查价语义。通过只表示客户端行为正确，不表示公司接口可用。
- `tests/test_execution.py`、`tests/test_review_regressions.py`：执行意图、未知不重传、保护历史、逐目标范围、日界与当前状态。
- `tests/test_worker.py`、`tests/test_api.py`：任务/租约、接口权限及配置边界。
- `tests/test_erp_validation.py`、`tests/test_erp_capture_diagnostics.py`：合成ERP抽样诊断、总数未知/矛盾、明确HTTP拒绝与普通失败区分、管理员访问和无执行副作用；不验证真实账号可见范围。
- `deploy/smoke-source-ui.py`：临时demo数据库和合成报告的浏览器验收，验证主动触发、部分拒绝、下载、失败清除旧结果和窄屏，不访问公司接口。
- `deploy/smoke-ui.py`：本地 demo 浏览器冒烟；会创建模拟任务，不访问真实改价系统。

涉及金额的预期值应手算或用独立算法产生，并覆盖临界值两侧。涉及提交的测试须使用临时数据库及模拟适配器，断言调用次数、锁状态、证据和其他独立目标是否继续，不只断言 HTTP 200。

真实费用模型校准另用经批准、脱敏的业务样本，覆盖将启用的站点/仓配、折扣和费用档位。合成样本不能标成真实验收样本；原始业务数据留在受控存储，不入 Git。

## 5. 变更检查与交付

改动前：读取相关业务基线，确认改动归属层、数据证据和受影响调用方。兼容与清理按 [AGENTS.md](../AGENTS.md) 执行；设计冲突先说明，不凭经验替换口径。

改动时：保持现有用户工作；公式、字段合同、注释和测试同步修改。持久结构变化使用 Alembic 迁移，保留未知执行、锁和历史；迁移在 worker 停止时执行。无需为文档或判定 JSON 中新增可选过程字段制造数据库迁移。

改动后：先在 `frontend` 执行 `npm.cmd run build`，再在项目根目录执行 `.venv/Scripts/python -m pytest`；两者顺序执行，避免测试初始化与前端产物清理冲突。按变更范围决定是否重跑浏览器、迁移检查或部署验证。未运行的验证明确列出，不能沿用历史结果冒充本次结果。

交付说明至少包含：修改范围、业务口径是否变化、验证命令/环境/结果、真实环境未验证项。测试数量记入带日期的验证记录，不在 README 固定宣传某个数量。

## 6. 配置与数据安全

- 默认空试点、真实提交关闭。环境开关、合同、站点及店铺授权都通过，才能进入真实提交路径。
- `.env`、真实合同文件、原始导出、数据库、日志、模拟回执与截图不入 Git。示例合同只使用占位信息，必须默认未确认。
- 日志不保存凭据、认证头、原始响应或带权限 URL。异常文案避免附带上游完整请求内容。
- 技术日志统一经 `app.observability.event` 白名单输出，事件名和中文文案静态定义；禁止把异常文本、进度文案、订单号、员工姓名、业务价格、外部任务名和URL当作字段。异常仅生成错误编号及安全堆栈定位。调用链用请求、任务、批次、执行、操作或采集的安全编号关联，不能以日志代替持久执行证据。ERP入口即使在demo进程主动请求真实ERP，也标记 `source=erp, synthetic=false`。
- 批量ERP核心通过可选 `event_callback` 注入日志，保持桌面独立构建不依赖 `app` 导入；桌面标准库日志只允许静态事件、阶段、计数、布尔状态、随机编号及安全文件名/函数名/行号，不保存用户输入或异常正文。日志配置、检索及轮转边界见[日志与排障](logging-and-troubleshooting.md)。
- demo、文件对账和真实运行使用独立数据库/运行目录；模式切换不能让演示历史充当真实证据。真实环境接入前要专门验证执行恢复的模式归属。
- 不读取或复用预算项目凭据，不修改其服务、目录和数据库。备份恢复不触发商品价格补偿或旧请求重发。

## 7. 初版已识别的设计限制

以下是当前实现与目标规范的差距，不因写入规范就视为完成：

- `FeeModel` 只表达一组仿射系数，没有价格适用区间；仅有站点费用版本校验不能证明分段/最低费用模型在目标价仍适用。
- 站点合同仍按站点索引，现在必须明确仓配适用列表，未覆盖的目标会阻断；但尚不能在同一站点同时配置多个不同上传列/费用版本的合同，也没有本土/跨境类型维度。不同范围不能因为站点已经开通就默认支持，须分期接入或确认设计后细分合同。
- 实时定价的 `HttpAdapter` 只支持同步列表及分页，显式拒绝异步导出合同。独立的 ERP 批量采集与文件算价入口见[ERP 只读数据采集](erp-source-capture.md)。
- 本地演示测试不能证明生产 Python 3.12、MySQL、容器、真实接口权限或平台有效价。相关验收逐项补证后才能开放试点。

优先顺序为：先取得数据及公式证据，再做文件对账和最小必要接入修正，最后按明确授权试点验证提交及真实价格。不要为了表面“可运行”填零、伪造字段或开启未经验证的真实执行。
