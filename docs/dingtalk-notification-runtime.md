# 钉钉机器人真实通知

生产由四部门定时任务生成销售员业务通知，机器人按本批 ERP 姓名私聊。网页查阅与商品操作沿用网站的归属权限。

## 当前通道

使用独立应用“亏损提价助手”，调用官方 `POST /v1.0/robot/oToMessages/batchSend`，每条通知只给对应销售员 `userIds` 一人发送。`processQueryKey` 存为 Notice.task_id；回执通过 `GET /v1.0/robot/oToMessages/readStatus` 查询。同一收件人的 READ 才记已读；SUCCESS+UNREAD 才记送达。已受理及结果未知不重发。查询24小时内分级降频，不用工作通知接口，也不使用个人账号。

应用凭据由该应用独立读取后保存在本机忽略的 `.env`（权限600），不随 Git 提交。真实通知只需要 clientId 和 clientSecret；corpId/agentId 仍属于原登录配置，不能把通知已接通表述为端内 SSO 已验收。

官网合同：
- https://open.dingtalk.com/document/development/chatbots-send-one-on-one-chat-messages-in-batches
- https://open.dingtalk.com/document/development/chatbot-batch-query-the-read-status-of-messages

## 本机常驻进程

WSL `/home/developer/projects/loss-repricing` 内运行 `.venv/bin/python -m app.notification_worker`，PYTHONPATH 指向 backend。该进程只打开配置指定的真实档案、为 live 批次生成去重通知和处理 outbox，不加载价格上传适配器、不领取价格任务。现有只读网页继续独立运行。

## 早间推送时间（2026-11-26 更新）

北京时间 08:00 前的新通知保留在持久待发队列，08:00 起按通知原入队时间逐条发送；08:00 后完成的任务仍照常推送，不设置晚间截止时间。不改变通知生成、收件人、内容、去重及结果未知不重发规则；已发送通知的回执查询不受早间延迟影响。管理员告警同样延后到 08:00。

钉盘日志不跟随推送延迟：常规日任务本轮全部待提价条目执行结束后，统一生成并写入两处日志，包含本轮成功、失败及待核验结果，不等待全部核验成功，也不新增完整性或时间戳校验。后台独立核验不再提前写入或反复刷新已完成的日志；只有整轮结束后的日志写入失败才沿用原有补写流程。

## 运行告警（仅常福生）

真实运行使用 `LR_DING_ALERT_USERID` 指定的常福生账号接收「亏损提价运行告警」：定时已启用但 08:00 仍未入队或开始、取数后等待重试、任务失败、运行超过 60 分钟未结束、任务租约过期、后台轮询异常、钉盘日志写入失败。长时间未结束是排查提示，不等于确认卡死。告警不发给销售员或主管，未配置管理员 User ID 时保留待发，不改发他人。销售员正常业务结果通知不变。

08:00 前发现的告警照常入队，08:00 后发送。按问题和任务（无任务时按业务日）去重，消息只含固定说明、发现时间和排查编号，不含原始异常正文。后台任务进程由独立线程处理告警和钉钉投递，取数、算价或归档卡住时无需等它们返回；本机独立通知进程也可检查所绑定的真实档案。若整个进程停止且没有独立通知进程绑定到同一档案，则无法实时发送告警。告警不会更改任务状态、终止任务、暂停站点或重传价格。

## 销售员通知（2026-11-26 更新）

固定七人名单、名单日期调度及专用提交／零库存续跑入口已删除，不再维护七人的姓名与部门限制。普通任务按原有定时开关运行，历史记录查询、下载和已提交／结果未知的独立核验保留。

## 两处钉盘提价日志（2026-11-25 用户确认）

两处各写一份 `M.D早上运行日志.xlsx`，不加姓名。`LR_DING_TK_MORNING_LOG_FOLDER` 及对应数字目录 ID 指向「集团二部每日数据 → TK亏损提价日志」；`LR_DING_CANCELLATION_LOG_FOLDER` 及对应数字目录 ID 指向罗迪的「集团二部每日数据 → 作废订单日志」。沿用已确认路径，不再等待或转发上游作废工作簿，也不改动罗迪自己的 `M.D上午运行日志.xlsx`。

本人目录的工作簿只有「明细」，列顺序为：处理时间、销售员、SKU、商品ID、产品ID、店铺ID、站点、仓配、状态、原实际营销价、目标实际营销价、上传价、币种、处理说明。读取当日真实持久记录及执行请求，沿用记录页的准备／失败过程合并规则；包含成功、待核验、待处理及不调价。商品ID对应 `item_id`，产品ID对应 `product_id`；时间显示北京时间，编号和金额原字符串不转浮点数。

罗迪目录的提价文件固定命名为 `M.D早上运行日志.xlsx`。「成功清单」四列为 `itemID`、店铺、销售、状态，「失败清单」四列为 `itemID`、店铺、销售、失败原因。「汇总」统计运行时间、总条数、成功/处理中、明确失败、已剔除。成功行的 `itemID` 取本次提价明细的商品 ID（`key.item_id`），按文本写入。已提价或已核验成功的记录按原执行请求关联来源订单，并按原始订单导出核对店铺和销售。排除已剔除的来源后，同一订单、店铺、销售和商品只计一次，同一商品涉及多笔订单时逐单保留。成功行标记为「提价成功」，失败清单仅保留表头。

后台常规日任务在本轮全部提价执行结束后统一写入两处日志，不随逐条完成或每分钟独立价格核验提前写入、反复刷新；历史名单任务与零库存续跑入口已删除。执行结束不要求全部核验成功，日志保留当时的成功、待核验、待处理及不调价结果。整轮结束写入时持久标记待补写业务日，只有两处都成功才清除；网络异常或进程重启后仍会补写原日期。两处独立处理，一处失败不阻止另一处，更不会因此重新取数或重传商品价格。内容不变复用本地工作簿和已核验上传回执；内容改变时更新各自目录中的同名日期文件。企业应用在同一次上传中只查询一次目标目录，提交响应能确认目标文件时直接保存回执，缺少文件身份信息时才补查文件；新建禁止重名，已确认同名文件使用官方提交文件接口的覆盖策略更新原节点。归档提交结果未知时保留发布意图和原始工作簿字节，不先用新版本覆盖待核验文件，停止自动重传，需核实远端结果后处理。

服务器 Worker 使用项目内的 systemd 配置片段加载亏损提价应用凭据，实际密钥和人员映射保存在服务器受限环境文件中。此处描述代码约定，部署与真实双目录上传需以对应验收回执为准。
