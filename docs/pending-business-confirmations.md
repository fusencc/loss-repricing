# 销售改价待核实事项

记录日期：2026-11-05。用户明确要求先标记，待其询问后再核实。

**当前信息：销售员可能在公司销售系统、平台后台两处改价。此信息尚未核实，不能当作已确认的数据来源或接口合同。** 本轮保留适配入口，真实调价与真实钉钉发送继续关闭。

| 待核实内容 | 需要取得的事实 | 对程序接入的影响 |
|---|---|---|
| 实际改价入口 | 各站点实际用哪些页面，修改零售价、营销价还是活动价 | 决定刷新与冲突比较字段，不能只比较一个价格数字 |
| 双系统同步关系 | 哪边向哪边同步、延迟、冲突时谁覆盖谁 | 确定权威现价与执行后读取路径 |
| 改价历史与操作者 | 能否取得变体、时间、前后价、操作者、来源、版本 | 证据不足仅标“外部变更”，不归因给销售员 |
| 写入并发约定 | 是否支持价格版本条件更新，或能否约定某范围独占写入 | 未确认前保持真实写入独占开关关闭，不能只靠提交前读取承诺防覆盖 |
| 责任人和主管名单 | 店铺/站点负责人、子SKU例外、指定主管、交接方式 | 管理员录入归属；缺归属的条目进入待处理 |
| 人员修正权限 | 哪些销售员可自行批准修正，哪些由主管批准 | 使用已有可配置修正权限，不为所有人默认放开 |
| 钉钉应用配置 | 企业内部应用、可见范围、人员userid、员工可达HTTPS入口 | 完成绑定和端内/浏览器验证后再验收真实发送 |

已确定的处理方式不因本清单而撤销：带权限网页作为处理入口；通知按责任人汇总；人工接管阻止尚未发送的自动调价；在途结果继续核验；明确交回后重新取数计算。具体操作见[销售协作与通知手册](sales-coordination-runbook.md)。
