### 已修正

1. **循环小数导致档位或零毛利误判。** 保留 Decimal 精确分子/分母，有限小数乘加、交叉积比较和商余数舍入不先使用循环小数近似。已复现并修正的例子包括正确应上传 4.00 却算成 3.99、半档应上传 0.47 却算成 0.46，以及目标毛利精确为零却因尾差被阻断。业务公式不变，不加利润容差。
2. **核验容限使用默认 Decimal 精度。** 新记录按持久化的精确目标比值核验，旧记录按原保存目标核验；比容限多出极小金额仍判超差，不能先舍入成恰好相等。
3. **确认标记的乐观默认。** 整单分摊可靠、销量完整、历史已知缺失时默认 false；合法演示及测试显式提供证据，不把缺字段当确认。同步 JSON Schema。
4. **仓配合同没有适用范围。** 增加明确 `warehouses`，默认空；领域判断和提交边界均拒绝未覆盖仓配。尚未实现同一站点同时配置多套不同上传列/费用版本。
5. **回读币种与观测年龄。** 查价合同须映射币种，并提供已确认的正整数 `max_age_seconds`；币种缺失/冲突或来源过旧保持未知。测试的 300 秒不代表真实接口已批准阈值。
6. **72 小时起算。** 缺少有效精确生效时间时，以本程序首次成功确认时间起算，分别保存观测时间、确认时间、生效保护时间及其来源。
7. **批内新增保护与模式隔离。** 领取执行意图前读取本地最新主 SKU 保护；只阻断匹配目标。核验按原批次模式过滤，拒绝跨模式重评/复用同批记录，不释放其他模式未知锁。
8. **规范与交付说明。** 整理公式规范和独立核对样例，新增代码设计规范，更新 AGENTS、README、来源证据及运行说明；真实合同默认路径加入 Git 忽略。
