# 亏损补亏工作台

**当前阶段：可本地运行的初版，用于规则核对和模拟流程；尚未完成真实数据接入、真实提价验收或生产部署。** 当前主要开发副本位于 WSL2 的 `/home/developer/projects/loss-repricing`；Windows 原目录 `D:\projects\loss-repricing` 是独立的迁移前副本，不会自动同步。其他机器可将项目克隆到自己的目录，以下命令需在各自的项目根目录执行。

程序针对亏损订单对应的具体在线子 SKU（可独立定价的商品变体），计算补亏价格、检查保护条件、记录执行过程并核验结果。现阶段可用合成数据演示，也可读规范化 JSON 文件对账；页面可运行、测试通过或模拟“已核验”，均不代表公司数据正确或平台价格已生效。

项目总体目标、核心验收要求与阶段划分见[项目总体验收标准](docs/acceptance-criteria.md)，作为后续开发规划和交付验收的依据。

## 1. 当前能做什么，尚缺什么

- **本地已实现**：独立子 SKU 取最小有效单件亏损、换汇、折扣反推、价格档位舍入、正常一次毛利复核；管理员/主管/销售员分权网页、店铺和子SKU归属、人工接管与交回、修正方案、持久任务、防重锁、未知结果恢复查询及模拟回执。
- **销售协作已实现**：员工仅查看和处理自己负责范围，主管处理指定范围；接管后停止尚未发送的自动调价，交回后重新取数。修正方案经权限和利润检查后排队执行，通知按负责人汇总，区分模拟、受理、已读与网页确认。使用方式见[销售协作与通知手册](docs/sales-coordination-runbook.md)。
- **文件对账可用**：读取 `Snapshot` 规范快照执行规则，适配器拒绝上传。结构见 [JSON Schema](docs/snapshot.schema.json)，合成样本见 [样本说明](tests/fixtures/README.md)。
- **真实接入仅有边界代码**：HTTP 适配器支持经确认合同的同步列表/分页、字段映射、单商品 Excel 提交和实际价查询；尚无可直接使用的公司完整取数合同，异步导出任务链未实现。
- **真实环境未验证**：四份 ERP 候选、在线唯一映射、销量与历史、当日汇率、公司费用模型、上传税后/仓配列、折扣保持、行级结果与当前有效价。实际试点尚未指定。
- **只读取数诊断入口**：管理员在「运行配置 → ERP 数据获取验证」主动读取真实四组第一页样本，查看读取失败、覆盖范围和待确认项并下载诊断报告；不代表全量或账号权限验收，不计算或提交价格。详见[ERP只读采集说明](docs/erp-source-capture.md)。
- **ERP 批量采集与对账**：CLI 和管理员 API 读取四类 TikTok 候选并保存财务原件。可按采集编号查历史订单，或使用补充证据生成[只读算价报告](docs/erp-pricing-preview.md)。入口见[ERP 只读采集](docs/erp-source-capture.md)。

`demo` 使用合成数据和本机回执；`file` 仅算价对账；`live` 是待接入的真实接口模式。默认真实提交关闭、试点名单为空；示例合同 [live-contract.example.json](deploy/live-contract.example.json) 为未确认模板，不能只改 `verified` 就认定验收完成。

## 2. 核心计算口径

业务基线是[已确认设计](docs/superpowers/specs/2026-11-05-loss-repricing-design.md)。完整变量、单位、精度、例子与来源统一维护在[核心计算与数据来源](docs/calculation-and-sources.md)，README 不另立一套公式。

规则概要：同一个具体在线子 SKU，在同店、同站、同仓配、同币种与同费用口径内，将有效亏损归一到单件后取最小亏损幅度；将其按当日汇率转换成站点币，加到当前实际价上；按当前成交比例反推含增值税（VAT）上传价，按已确认档位舍入，再复核目标价和舍入后实际价的正常一次毛利均不为负。

计算使用 `Decimal`。本期不使用旧 15% 目标利润、统一涨 1%、额外利润或跨子 SKU 共享亏损；直接补亏仍亏损时转待处理，不自动反算更高价格。公司费用参数和平台折扣行为仍须真实样本核对。

主 SKU 前七个完整北京时间自然日销量达到 21 件、人工保护、现价已不亏等按规则排除；活动、未知历史及不可靠数据进入待处理。已确认生效不足 72 小时不再提价；已有未知提交持续锁定，不重传。

## 4. 如何理解结果

用户状态为“本轮不调、待处理、待核验、已核验”。算价通过、上传受理、行处理结果和实际有效价是不同证据阶段：

- `ready=true` 只表示计算通过，还需通过提交授权、合同、刷新和防重检查。
- 受理或结果未知仍是待核验；未知时只查询，不自动重传。
- demo 的“已核验”只表示模拟价格核验；真实模式只有同商品、仓配、币种、价格口径及有效时间证据通过，才能确认实际价。
- 实际价超差暂停该站点新提交，仍继续查询旧提交。批次“已完成”不等于全部商品已生效。

单条重评只处理选中目标；全局概览展示每个实际目标的最新评估，并保留旧未终结执行。批次详情保留历史，不用新结果覆盖旧证据。

## 5. 技术与开发约束

后端为 Python/FastAPI、SQLAlchemy/Alembic 和持久 worker；前端为 Vue 3、TypeScript、Vite、Element Plus。本地演示采用 SQLite，生产规划采用独立 MySQL。生产目标 Python 3.12，本地兼容并验证 Python 3.13。

- `backend/app/domain/`：内部模型与纯计算。
- `backend/app/adapters/`：演示、文件、真实合同边界和模板。
- `backend/app/services/`：批次、执行意图、防重、核验和当前记录查询。
- `backend/app/worker.py`：调度、任务租约和恢复。
- `frontend/`：管理网页，仅展示后端金额，不重算业务价格。
- `tests/`：离线规则、适配器、执行与恢复测试。
- `deploy/`：启动、停止、界面检查及部署预留。
- `runtime/`：本机数据库、回执、日志和截图，不入 Git。

开发须遵循 [AGENTS.md](AGENTS.md) 和[代码设计与变更规范](docs/engineering-standards.md)。核心来源、公式、执行路径必须有中文依据注释；金额不使用 `float`。真实合同、凭据及原始业务数据不入 Git。不同运行模式使用隔离数据库与运行目录，不复用预算项目凭据或服务。

## 7. 真实接入的下一步

1. 核实四份 ERP 候选的筛选条件、明细键、数量、金额粒度和币种；核实在线身份、价格、保护、销量和历史来源，先只读取数对账。
2. 提供公司批准的正常一次毛利分项公式、版本和脱敏样本，核对广告/营销排除、税基、物流、汇率及费用档位；用文件模式逐项复算。
3. 确认试点站点及仓配的含税上传列、价格档位与舍入方式，验证上传后折扣行为、逐行拒绝及实际价查询证据。
4. 完成初版接入限制的必要修正及恢复测试，再在明确授权的店铺/站点试点；默认继续关闭真实提交。结果未知时只查询，不用重传试探。

已发现的代码设计限制详见[开发规范第 7 节](docs/engineering-standards.md#7-初版已识别的设计限制)；现有接口历史证据及缺口详见[数据合同证据](docs/data-contract-evidence.md)。钉钉登录和定向工作通知适配已实现，默认仅模拟；企业应用、真实人员绑定、端内免登和真实送达尚未验收。销售员可能在公司销售系统和平台后台改价，此信息仍待用户核实；不据此推定接口或并发控制能力。程序不改历史订单、不解除禁止发货、不自动退出活动。
